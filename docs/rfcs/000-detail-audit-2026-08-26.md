# RFC Detail Audit

**Date:** 2026-08-26  
**Scope:** [RFC 001](001-guided-release-kit.md) through [RFC 033](033-workspace-migration.md)

## Purpose

This audit identifies which RFCs need additional product or implementation detail before engineering work can proceed safely. It evaluates whether each RFC defines its contracts, lifecycle, authorization, failure behavior, rollout, and testable completion criteria.

## Recommended expansion order

The roadmap marks RFCs 019 and 020 as implemented. Their gaps are documentation backfill and should be reconciled against the shipped behavior rather than used to redesign it without a migration decision. For unimplemented work, add detail before implementation begins.

Prioritize the audit backlog as follows:

1. **Backfill shipped external-action contracts:** [RFC 019: Campaign Approval Workflow](019-approval-workflow.md) and [RFC 020: Postiz Publishing Abstraction](020-postiz-publishing.md)
2. **Specify future external boundaries:** [RFC 022: GitHub Integration and Marketing-Worthy Change Detection](022-github-integration.md) and [RFC 027: Post Performance Analytics](027-analytics-ingestion.md)
3. **Specify policy and autonomy boundaries:** [RFC 030: Approval Policies](030-approval-policies.md) and [RFC 031: Autonomy Modes](031-autonomy-modes.md)
4. **Specify the next roadmap implementation:** [RFC 010: Programmable Creative Engine](010-programmable-creative-engine.md)
5. **Specify AI execution:** [RFC 016: AI SDK and Typed Marketing Tools](016-ai-sdk-marketing-tools.md) and [RFC 017: Conversational Campaign Creation](017-conversational-campaign-creation.md)
6. **Specify capture and rendering automation:** [RFC 023: Deployment-Driven Screenshot Automation](023-deployment-screenshot-automation.md) and [RFC 024: Product Demo Video Generation](024-demo-video-generation.md)
7. **Specify recurring execution:** [RFC 029: Recurring Campaign Generation](029-recurring-campaign-generation.md)
8. **Harden onboarding operations:** [RFC 032: Background Onboarding Agent and ICP Extraction](032-background-onboarding-agent.md)

## Sufficient for current purpose

- [RFCs 001–008](001-guided-release-kit.md) are generally implementation-grade. They consistently cover decisions, boundaries, security, reliability, rollout, and acceptance criteria.
- [RFC 009](009-marketing-platform-thesis.md) is appropriately scoped as a product thesis. It should link requirements to downstream RFCs rather than become an implementation specification.
- [RFC 033](033-workspace-migration.md) adequately records the decision not to migrate yet and defines triggers for revisiting it.

## Standard sections to add

Short product RFCs should use a shared expansion checklist:

1. Goals and non-goals
2. User and system workflows
3. Typed data and API contracts
4. Lifecycle or state machine
5. Authorization and tenant isolation
6. Failure, retry, cancellation, and idempotency behavior
7. Security and privacy threats
8. Observability and cost limits
9. Rollout and migration plan
10. Testable acceptance criteria
